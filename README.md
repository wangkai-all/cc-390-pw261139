# 宽表拆分迁移演练台

把既有分析宽表拆成 **主记录 / 重复子项 / 历史修订** 三类表，下游旧查询接口暂时保留。
接入转换器、新版存储、兼容查询服务各自独立运行；双写与日志重放两条迁移路径并存，
全量对账保证两套结果不偏离，差异可定位到原批次。

## 架构

```
                 ┌──────────────┐
   写入 ───────▶ │ 接入转换器 :8001 │  1) 版本号向旧系统要（迁移期排序事实源）
                 └──────┬───────┘  2) 先写接入日志 data/ingest_log.jsonl（fsync）
                        │          3) 双写两侧
              ┌─────────┴──────────┐
              ▼                    ▼
   ┌────────────────┐   ┌─────────────────────┐         ┌──────────────────┐
   │ 旧系统 :8004    │   │ 新版存储 :8002        │ ◀────── │ 兼容查询服务 :8003 │
   │ wide_rows 宽表  │   │ masters 主记录        │  重组    │ 旧接口同契约       │
   │ /api/v1/report │   │ sub_item_groups 分组 │         │ /api/v1/report   │
   └────────────────┘   │ sub_items 子项行      │         └──────────────────┘
                        │ revisions 历史修订    │  故障/重放/对账演练：
                        │ batches 批次注册      │  网页 :8000（四个页签）
                        └─────────────────────┘
```

- **拆分不是改字段名**：顶层数组字段拆成子项行（`seq` 保序、重复项各占一行、
  空数组保留 `count=0` 分组行以区别于字段缺失），每次改版在 `revisions` 留痕，
  兼容服务按 `assemble` 逆运算实时重组出与旧接口逐字节等价的宽表记录。
- 双写与重放共用 `app/core.py` 里同一个 `split` 纯函数，两条路径产出必然一致。

## 运行

```bash
bash scripts/start_all.sh     # 启动全部五个服务（数据 ./data，日志 ./logs）
# 打开 http://127.0.0.1:8000
bash scripts/stop_all.sh      # 停止
```


## 网页四个页签

1. **导入嵌套记录**：粘贴/填入示例 JSON → 拆分预览（三类表投影）→ 导入（写日志+双写）。
2. **记录与改版**：记录清单、历史修订时间线、编辑 JSON 提交改版生成新版本。
3. **新旧查询对比**：同一输入版本分别查旧接口与兼容服务，并排展示 + 逐路径差异；一键全量对账。
4. **迁移与故障演练**：注入「新版存储故障」→ 导入积压为待重放 → 恢复后重放追平 → 对账确认；
   「兼容服务故障」演示查询侧晚恢复；点批次号可查看该批次的原始输入。

## 关键设计（详见 docs/migration.md）

- **防偏离**：日志先行（WAL）+ 版本号入日志 + 同一拆分纯函数 + 幂等应用 + 三方校验和对账。
- **差异定位**：每条修订带 `batch_id`，对账差异 → 批次号 → 接入日志行 → 原始输入，可单批重放修复。
- **晚恢复**：新版存储故障期间批次标记 `pending_replay`，恢复后 `/replay` 按日志顺序幂等追平。
